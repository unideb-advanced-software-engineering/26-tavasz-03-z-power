- **Status:** Active
- **Supersedes:** ADR-005

**In the context of**
- a Container-szintű elemek deployment-topológiája az ADR-002 (EDA) és ADR-003 (Microkernel) alrendszerein belül

**facing the need for**
- 7/24 rendelkezésre állás SPOF* nélkül a kritikus adatútvonalon (REQ-04)
  - *SPOF: Single Point of Failure
- horizontális skálázhatóság több tízezer termelőhöz (ZP-NF-PERF-01)
- a diszpécserközponti integráció kiesésmentessége - ASR szerint nem opció
- a ZDR takarékossági elv: ne fusson felesleges példány
- az ADR-005 logikai SPOF-jainak feloldása és a Persistence Worker sorrendiségi problémájának kezelése

**we decided for**
- **multipleInstanceService**:
  - **REST API Gateway, MQTT Broker** - belépési pontok, kiesésük adatvesztés (REQ-01, REQ-04)
  - **Normalizer** - állapotmentes, magas áteresztőképesség (REQ-02, REQ-03)
  - **Fault Detector** - tízezres termelőszám párhuzamos figyelése (REQ-07, REQ-08)
  - **Schema Registry** - *V1-hez képest változás:*
    - rendelkezésre állás a Normalizer felé
    - egy példány kiesése ne állítsa meg a feldolgozást
  - **Notification Service** - *V1-hez képest változás:*
    - tömeges üzemzavarnál ne legyen szűk keresztmetszet (REQ-10)
  - **Microkernel Core** - *V1-hez képest változás:*
    - az `as.md` "korlátozott skálázhatóság" kompromisszum feloldása
  - **Dispatcher API** - *V1-hez képest változás:* 
    - kritikus külső fogyasztó (a diszpécserközpont) kiesésmentessége
- **service**:
  - **Persistence Worker** - *V1-hez képest változás:* 
    - egyetlen instance, batch-elt írással bőven elbírja a forgalmat (TimescaleDB szereti a nagy batcheket)
    - és így biztosított az idősor beérkezési sorrendje (FIFO a topicról)
    - a szűk keresztmetszet a DB, nem a worker

**neglecting**
- **ADR-005 topológia:** a single-instance Microkernel Core és Dispatcher API SPOF-ot jelentett, a Schema Registry és Notification Service csúcsterheléskor szűk keresztmetszetet okozott
- **többpéldányos Persistence Worker (ADR-005):** növelte az írási áteresztőképességet, de a párhuzamos consumerek megtörték a beérkezési sorrendet az idősoros tárolásnál, torzítva az analitikát és az előrejelzést

**achieving**
- skálázhatóság az adatútvonal teljes hosszán
- a Persistence Workernél a beérkezési sorrend megőrzése; erőforrás-fókusz a tényleges szűk keresztmetszetre (TimescaleDB)
- a Microkernel Core "korlátozott skálázhatóság" kompromisszumának feloldása (`as.md`)
- a Dispatcher API kiesésmentessége a diszpécserközpont felé

**accepting that (we will have)**
- magasabb infrastruktúra-költség és üzemeltetési komplexitás az ADR-005-höz képest
- a Persistence Worker mint logikai SPOF: kiesésekor a Normalized Topic puffereli az adatot, nincs adatvesztés, de a perzisztálás (REQ-13) késik a worker újraindulásáig
- a többpéldányos Microkernel Core több szakértelmet igényel
